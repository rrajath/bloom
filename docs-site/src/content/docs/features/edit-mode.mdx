## Syntax highlighting

Bloom tokenizes each line and applies color per syntax element as you type:

- Heading stars (`*`, `**`, `***`): colored by nesting depth, cycling through the same star-color sequence used in Outline View
- TODO/DONE keywords
- Timestamps (`<...>`, `[...]`)
- Tags (`:work:planning:`)
- Property-drawer keys and `:LOGBOOK:` contents

This is implemented with a custom `VisualTransformation` over a `BasicTextField`; there's no separate preview pane, the highlighting applies directly to the text you're editing.

## Formatting toolbar

A toolbar pinned above the keyboard gives one-tap access to common org markup:

| Icon | Inserts |
|---|---|
| **B** | `*bold*` |
| *I* | `/italic/` |
| U | `_underline_` |
| `</>` | `=code=` |
| ☑ | `- [ ]` checkbox item |
| `[[ ]]` | link at the cursor (tap); **long-press** for the file/heading picker, below |
| 🕐 | timestamp: tap for a date, long-press to open a date/time picker |
| `*` | new heading |
| `«` `»` | list indent/outdent |

### Inserting a link

**Tapping** `[[ ]]`:

- with **text selected**, inserts `[[https://][<your text>]]` with the cursor right after `https://`, ready to type or paste the address. If you paste a URL that already starts with `https://` or `http://`, the duplicate scheme is folded away.
- with **nothing selected**, inserts `[[link][description]]` with `link` selected, ready to type over.

**Long-pressing** `[[ ]]` opens a full-height picker, search box focused and keyboard up, to link to a file or heading anywhere in the vault. It always starts at the notebook list, never the file you're editing.

- Typing filters live across every file and heading in the vault; a file icon marks a file, the five-spoke asterisk marks a heading, and each heading result shows its breadcrumb path.
- Without typing, tap a notebook to drill into its headings, then its sub-headings. Tapping a heading with no sub-headings links it immediately; only a heading with sub-headings drills in further.
- At a notebook's top level, **Link to this file** writes `[[file:other.org]]` (just `[[file:name.org]]` for a link into the note you're editing). **Link to this heading** writes `[[*Heading]]` for a heading in the note you're editing, or `[[file:other.org::*Heading]]` for one in another file.
- If the picked file has a file-level `ID`, or the picked heading has an `ID` or `CUSTOM_ID`, Bloom asks whether to use that instead — an id link keeps working after the target is renamed or moved.

Text you have selected when you long-press is kept as the link's description. With nothing selected, the link is named after its target — the heading title, or the file's `#+TITLE:` (falling back to its file name).

### Inserting a timestamp

**Tapping** 🕐 inserts an inactive date-only stamp (`[2026-01-15 Thu]`) at the cursor.

**Long-pressing** 🕐 opens a single-day date/time picker, pre-selected to right now: a calendar plus Today/Tomorrow/This weekend/Next week chips and an optional time. **Apply date** inserts the resulting inactive stamp (`[2026-01-15 Thu 14:30]`) at the cursor; a plain logged moment, not a SCHEDULED/DEADLINE/ACTIVE planning line, so it never shows up on the agenda.

### Inserting a block or drawer

Type a shorthand at the start of a line or after a space, and a chip appears above the keyboard. Shorthands are case-insensitive (`<Q` works like `<q`, `:pro` like `:PRO`):

| Type | Chip | Inserts |
|---|---|---|
| `<q` | Insert quote? | `#+BEGIN_QUOTE` … `#+END_QUOTE` |
| `<e` | Insert example? | `#+BEGIN_EXAMPLE` … `#+END_EXAMPLE` |
| `<s` | Insert src? | `#+BEGIN_SRC` … `#+END_SRC` |
| `:PRO` | Insert properties drawer? | `:PROPERTIES:` … `:END:` |
| `:LOG` | Insert logbook drawer? | `:LOGBOOK:` … `:END:` |

The drawer chips keep showing as you type more of the keyword, up to the full `:PROPERTIES:` or `:LOGBOOK:`.

Tapping the chip replaces the shorthand with the block or drawer. The cursor lands on the empty line inside it; for src it lands after `#+BEGIN_SRC ` so you can type the language first. If the line already has other text, that text stays where it is and the snippet starts on the next line. The snippet matches the line's indentation, so one typed in a list item stays in that item. Keep typing something else and the chip goes away.

The chips work in the note editor, the capture editor, Dailies, and the intro and whole-file editors. Block chips never show in a file's preface (its `#+KEY:` lines); drawer chips show anywhere.

## Instant Read ↔ Edit switching

The **Read / Edit** toggle at the top swaps modes in place: no navigation transition, no extra back-stack entry. Tap anywhere on the toggle to switch. **Switching to Read mode never saves**: Read mode shows your unsaved text, marked by a green save icon (tap it to save). Leaving the note with unsaved changes asks whether to save or discard them.

## Autosave

Edit mode saves automatically:

- After roughly 5 seconds of idle typing
- Immediately when you switch to Read mode
- The save indicator (a floppy-disk icon) shows **green** for unsaved changes (tap it to save immediately) and **grey** once saved; tapping the grey icon shows a "last saved at" toast

## Stale-file protection

Before saving, Bloom checks the file's on-disk revision. If something else changed the file since you opened it (another device via sync, an external editor), you're prompted to **Overwrite** or **Reload** rather than silently clobbering the other change.

## Discarding a blank note

If you open a brand-new, still-empty note and try to leave without adding content, Bloom asks for confirmation before discarding it, so an accidental capture doesn't quietly vanish, but an accidental tap also doesn't leave an empty heading behind.
