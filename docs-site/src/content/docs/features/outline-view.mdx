Opening a notebook from the Notebooks list lands you in Outline View, a flat, scrollable list of every top-level heading in the file, rendered as rich rows rather than raw text.

## What each row shows

- **TODO/keyword chip**: TODO, NEXT, WAITING, DONE, or whatever keyword set you've configured in Settings → Notes
- **Priority**: `[#A]`, `[#B]`, `[#C]` shown as a bracketed tag next to the keyword
- **Title**
- **Tags**: right-aligned, colon-wrapped (`:work:planning:`)
- **Body preview**: the first line or two of the heading's text content, truncated
- **Planning chips**: a calendar icon for SCHEDULED, a flag icon for DEADLINE, and a violet `●` chip for each bare active `<date>` event, shown below the title when set (events gated on the outline's Timestamps toggle)

A heading marked DONE renders with strikethrough and dims slightly, but stays in place in the list (Outline doesn't auto-hide completed items the way Agenda's filters can).

## Preface and property drawers

If the file has file-level `#+KEYWORDS:` (like `#+FILETAGS:`) or a heading has a `:PROPERTIES:` drawer, they render as collapsible, monospace blocks: tap the disclosure triangle to expand, double-tap to edit that block's raw text on its own. These are controlled by the **Show preface** / **Show property drawers** toggles in Settings → Notes; turn them off if you don't want the visual noise.

## The intro

Text that sits above a file's first `*` heading (the whole body, for a heading-less org-roam style note) is the file's **intro**. It is not a heading, so Bloom gives it a row of its own above the outline's headings, showing the content in full. Tapping it opens the intro on its own in Read mode, and the Read/Edit toggle there edits just that text: the `#+` keyword lines and the property drawer above it keep their own double-tap editors.

The intro counts as one of the notebook's notes and is searchable like any other. Applying metadata to it (a TODO state, a priority, a tag) needs a heading to hang off, so Bloom inserts a blank `* ` heading above the content first and reopens it as an ordinary note.

## Swipe actions

Swiping a row left or right reveals quick actions without opening the note:

- **State**: opens the same state picker used elsewhere, to cycle the TODO keyword
- **Schedule**: opens [Planning Dates](/features/planning-dates) to set SCHEDULED/DEADLINE
- **Note**: appends a timestamped note to the heading's `:LOGBOOK:` via a small dialog, without leaving the outline
- **Favorite** (★): toggles the heading as a favorite, surfaced in the nav drawer
- **Add heading above / below**: inserts a new sibling heading
- **Add subheading**: inserts a new child heading, nested one level deeper
- **Refile**: opens the [Refile](/features/refile) picker to move this subtree elsewhere

## Move & indent

Long-press a row to lift it into focus mode: the top bar becomes the **Move & indent** bar, titled with how many headings are selected, with buttons to move the heading up or down among its siblings, promote or demote it (with its whole subtree), or delete it.

While the bar is showing, tapping other rows adds them to the selection (tap again to drop one). Each command then runs on every selected heading in turn:

- A selected heading inside another selected heading's subtree moves with that ancestor and isn't acted on separately.
- Adjacent selected siblings move up or down together as a block, and stop together when the first one hits the edge.
- A heading the command can't apply to (a top-level heading on promote, say) is skipped, and the snackbar says how many changed.

The whole batch is a single [undo](/features/undo) step. Tap ✕ or Back to leave focus mode.

The bar's ☰ button opens the same metadata sheet as [Read mode](/features/metadata-sheet). With one heading selected it behaves exactly as it does there. With several, each change applies to all of them:

- **State** and **Priority** chips highlight a value only when every selected heading shares it. A state change follows the usual done rules (a CLOSED stamp, repeating dates advancing, and auto-archive when that's on).
- **Tags** lists only the tags every selected heading has. Adding a tag adds it to each one, and removing a tag removes it from each one, without touching their other tags.
- **Dates** shows a date only when every heading has the same one, and "multiple" when they differ. Only the dates you change are written, so setting a SCHEDULED date leaves each heading's own DEADLINE alone. To clear a date that differs, open its tab and tap **Remove from all**.
- **Add note** logs the same note on each heading, and **Generate org-id** gives an `:ID:` to every heading that lacks one. Favorite is only offered for a single heading.
- **Refile** opens the [Refile](/features/refile) picker for all of them. Their subtrees land under the chosen heading in their original order, and a selected heading inside another selected heading's subtree travels with it. The one-tap Archive row appears when every selected heading archives to the same place.

Each bulk change is its own undo step.

## Narrowing to a subtree

If you arrive at Outline View from a breadcrumb link inside a note (tapping a parent heading), the view can narrow to just that subtree instead of showing the whole file, useful for focusing on one section of a large notebook.

## Opening a note

Tap anywhere on a row's title/body area to open that heading in [Read mode](/features/read-mode).

## Viewing the whole file

The `⋮` overflow menu's **View file** opens the entire file as one note: the file-level property drawer, the preface, the intro and every heading in a single Read scroll, with the same Read/Edit toggle as a note. Edit mode there is the whole file in one editor, so a small org-roam style note can be read and rewritten in one place without drilling into headings.

To keep large files from freezing the editor, View file is only enabled for files of up to 1,000 lines. Above that the item is greyed out with the file's line count, and you open a heading instead. Tapping the file name in the whole-file view returns to this outline.

With **Open roam files directly in read mode** turned on under Settings → Roam Features (the default), opening an org-roam notebook that fits under that limit skips the outline entirely and lands on the whole-file view, in your default note mode. Larger notebooks, and non-roam notebooks, still open here. Turning the toggle off sends roam files back through the outline too, regardless of size.
