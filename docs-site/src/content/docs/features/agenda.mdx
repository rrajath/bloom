Agenda pulls every SCHEDULED and DEADLINE item across your whole vault into a single day-by-day timeline, separate from browsing notebook-by-notebook. Bare active `<date>` timestamps (events) join it too, each shown on its exact day with a violet `●` chip.

## Today / Upcoming tabs

- **Today**: everything scheduled or due today, plus an **Overdue** card for anything past its date. Events only ever appear on their own day, never in the Overdue card
- **Upcoming**: an infinite-scroll timeline of future days, grouped under day headers like "Tuesday, Jul 28 · Today"

Swipe left on the list's empty space to go from Today to Upcoming, and right to go back. Swipes that start on a task row still trigger that row's swipe actions.

## Overdue card

Collapsible by default; expanding it lists every overdue item with a **Move to today** bulk action to reschedule everything at once.

## Row anatomy

Each row shows a priority-tinted checkbox (tap to mark done), the TODO/keyword chip, the title, a metadata line (date, "Xd late" for overdue items, tags), and a priority badge on the trailing edge. Tapping the row opens the note; tapping the checkbox toggles DONE in place.

A heading with no TODO keyword is an event, not a task, whether it lands on the day by a bare active `<date>` timestamp, a SCHEDULED date, or a DEADLINE. A plain event shows no checkbox and no "mark done" swipe. But when that same keyword-less timestamp carries a repeater cookie (`+1w`, `++1d`, `.+1m`), the row still gets the checkbox and swipe — tapping it advances the timestamp to its next occurrence instead of setting a DONE keyword, the same as completing it from a notification. Marking any recurring item done shows a snackbar with the new date, for example "Marked done. Next occurrence Jun 5th" (with the year added when it rolls into the next year). A heading that carries a keyword is still a task and keeps the ordinary checkbox/swipe, even when it also has an active timestamp. A repeating active timestamp (`<2026-10-28 Wed 12:00-14:00 +1w>`) shows on its own date and on every later occurrence, the way the Emacs agenda shows it, whether it sits on its own line or inside a sentence. When an event sits under a day heading, its metadata line drops the day (the heading already shows it) and keeps just the time range, if any.

A row whose title is in a right-to-left language (Persian, Arabic, Hebrew) mirrors: the checkbox and state chip move to the right and the priority badge to the left, and the title reads right-to-left. Swipe actions keep their usual sides.

## Levers panel

A collapsible panel above the list controls how items are grouped and filtered, and persists your choice between sessions:

- **Group by**: Date, Priority, Tag, or File
- **Show**: Open items only, specific configured keywords, or Everything
- **Display toggles**: show/hide tags and source-file names per row; a third toggle (off by default) adds scheduled-date and bare-active-timestamp chips next to the deadline chips a row already always shows — styled like Read mode's date chips (a calendar/dot icon plus colored text) but without their pill background

## Swipe-to-commit

Swiping an Agenda row left or right triggers a configurable action: by default, swipe left sets a Scheduled date and swipe right marks the item Done. Both directions are reconfigurable in Settings → Agenda (see [Notes Behavior](/features/notes-behavior) for the settings surface). Every swipe mutation is reversible via an [undo snackbar](/features/undo).

On a plain event row, the side configured as Mark as Done offers Add note instead, since there's nothing to complete. A keyword-less row with a repeater still gets the Done cell, advancing the date on swipe.

Mark as Done rides with an **Add note** cell, and Schedule with a **Reveal** cell. On those sides a long swipe commits the configured action, and a shorter swipe opens the row with both cells, the configured action at the edge. **Reveal** opens the heading's notebook in [Outline View](/features/outline-view), scrolled to that heading. A long swipe has to travel most of the row's width. As it does, the inner cell fades out and the row's background fills with the committing action's color, turning solid once releasing would fire it.

## Home-screen widget appearance

Settings → Widget is a dedicated page for the home-screen Agenda ledger widget (not the [quick-capture widget](/features/widget)): background Transparency, how many Days ahead to show, per-row Filename/Tags/Priority toggles, and a Small/Medium/Large Font size, with a live preview below the controls that updates as you change them. These are independent of the in-app Levers panel above — changing how the widget looks never changes the Agenda screen. A shown filename contracts each nested folder to its first letter (`Work/Projects/notes.org` → `W/P/notes.org`); the file's own name stays whole.

The widget lists the same rows as the Today/Upcoming view: scheduled and deadline items, an Overdue section, and bare active `<date>` events on each day they fall. Plain event rows carry no mark-done circle, since an event is not a task, and no repeated day label under the row. A keyword-less row with a repeater still gets the circle — tapping it advances the timestamp, same as in the Agenda screen.

In the widget's header, tapping the "Agenda" title (or the counts under it) opens the Agenda screen directly; tapping the app icon beside it opens Bloom wherever you left it.
