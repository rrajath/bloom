## Reminder notifications

When a heading's planning date arrives, Bloom fires a system notification. Whether it reads as a task or an event, and which actions it carries, depends only on whether the heading carries a TODO keyword — not on which timestamp field (SCHEDULED, DEADLINE, or a bare active `<date>`) triggered it.

### Task reminders

A heading with a TODO keyword is a task: the notification reads "Your task is due now" and always carries both actions:

- **Complete**: marks the heading DONE directly from the notification
- **Reschedule**: opens [Planning Dates](/features/planning-dates) to set a new date

### Event reminders

A heading with no TODO keyword is an event: the notification reads "Your event is starting now" (or "starts in ..." for a lead time) and carries only **Reschedule** — unless the timestamp itself carries a repeater cookie (`<2026-09-11 Fri +1w>`), in which case it also gets **Complete**, which advances the timestamp's own date rather than marking anything DONE, whether the timestamp sits on its own line or inside a sentence. A date-only event doesn't fire its own notification by default; it is folded into the daily digest for its day (turn on "Notify for tasks without a time" below to get a separate notification instead). A date range reminds you once, on its start date.

### Repeating timestamps

A timestamp with a repeater (`+1w`, `++1d`, `.+1m`, `+2h`) reminds you on every occurrence, not only on the date written in the file. A weekly meeting written as `<2026-10-28 Wed 12:00 +1w>` reminds you every Wednesday at noon, and after each reminder fires the next one is set up automatically. This applies to SCHEDULED, DEADLINE and bare active timestamps alike, so a recurring task you haven't marked done keeps reminding you on each repeat. Marking it done (or tapping **Complete**) moves the date in the file forward as usual. The daily digest still counts an unfinished recurring task as overdue, the same way the Agenda does.

Tapping the notification body itself deep-links into the note in Read mode.

## Reschedule without opening the app

The Reschedule action opens Planning Dates inside its own transparent, taskless activity, not the main app. That means rescheduling from a notification never actually navigates into Bloom; you set the new date and land right back wherever you were (home screen, another app, the lock screen).

## Daily digest

If enabled, Bloom sends one daily notification ("You have X tasks due today") covering overdue items plus anything due today, including any date-only events on today's date. It fires at your configured default reminder time and deep-links straight to Agenda. If the count would be zero, the digest is suppressed rather than sending an empty notification.

## Notify for tasks without a time

By default, a SCHEDULED, DEADLINE, or active timestamp that lands on a day with no time of day is only counted in the daily digest. Turn on **Settings → Reminders → "Notify for tasks without a time"** to get a separate notification for each of them, fired at the default reminder time on its day. The daily digest keeps working alongside it. Only tasks whose day is today or later are notified; a date that has already passed stays silent.

## Permissions

Reminders depend on two kinds of access, and Bloom asks for neither before you've turned reminders on:

- **Notifications.** Without them no reminder can appear. If a reminder is waiting on this permission, a banner on the Notebooks screen offers to grant it.
- **Alarms & reminders (exact timing).** Android 12 and later gate exact alarms behind this setting, and Android 14 and later leave it off for new installs. Without it, reminders still fire, but Android may delay them by up to an hour.

While reminders are on and access is missing, Settings → Reminders shows a row with an **Allow** button that takes you to the right system screen: **Notifications** first, then **Exact timing** once notifications are allowed (exact timing has no effect while notifications are off). The row disappears once access is granted. Granting or revoking exact timing re-arms every upcoming reminder straight away, so existing reminders switch to the new timing without needing to be edited.

If reminders are on, notifications are allowed, and exact timing is off, Bloom asks once with a **Get reminders on time** dialog. **Allow** opens the Alarms & reminders screen; **Not now** dismisses it for good and points you to Settings → Reminders → Exact timing for later.

## Surviving a reboot

A boot receiver re-arms all scheduled alarms after the device restarts, and fires any reminder that was due while the device was off but hasn't been seen yet.

## Settings

Settings → Reminders covers: the enable/disable toggle, the "Notify me" lead time for timed reminders, the "Notify for tasks without a time" toggle, the Morning Brief (daily digest) toggle, the default reminder time (used by the digest and by any timestamp without an explicit time), and, only while access is missing, the Exact timing and Notifications rows.
