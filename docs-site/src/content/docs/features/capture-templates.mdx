## Creating and editing a template

A template's **Name** also drives the monogram icon (its first letter) shown as the tile in the Capture picker; long-press the tile on the edit screen to pick its color.

With [Roam Features](/features/settings-overview#roam-features-experimental) on, a **Type** switch chooses what the template captures:

- **Add to a file** (the default, and the only option with Roam Features off):
  - **Target file**: which notebook the entry gets written to
  - **Insert location**:
    - **Top of file**: prepended right after any file-level preface
    - **Bottom of file**: appended at the end
    - **Under heading**: inserted as a child of a specific heading, matched either by exact heading name or by the heading's `ID` (the recommended match target, since it survives the heading being renamed). A `CUSTOM_ID` typed into the ID field also matches, so older templates keep working
      - If the template body doesn't start with a heading (for example `- [ ] %cursor` under a "Shopping List" heading), the capture adds content to that heading's body instead of creating a new child heading. The capture editor shows the target heading greyed out above the text so you know where it goes, and it can't be edited. "Last" appends to the end of the heading's own text, above any sub-headings; "first" puts it right after the heading's properties. Only a completely blank capture is refused
    - **Datetree**: auto-creates a Year → Month → Day chain of headings if it doesn't already exist, then inserts under today's day heading. Use `%U` for a stamp with the time or `%u` for the date only
  - **Template body**: the org text to insert, including any [placeholder](/features/placeholders) tokens
- **New node file**: see [Roam node templates](#roam-node-templates-experimental) below

Templates are reorderable: drag to change the order they appear in the Capture picker.

Deleting a template (the `✕` on its row in Settings) asks you to confirm first. Notes you already captured with that template are untouched; only the template definition goes away.

## Built-in templates

Bloom ships with three, all editable or deletable like any other:

| Name | Target file | Location | Body |
|---|---|---|---|
| Journal Entry | `journal.org` | Datetree | `%U %cursor` |
| Quick Note | `inbox.org` | Bottom of file | `* %cursor` |
| TODO | `tasks.org` | Bottom of file | `* TODO %^{Title}` then `%cursor` |

## Roam node templates (experimental)

Gated behind [Roam Features](/features/settings-overview#roam-features-experimental): instead of inserting into a fixed target file, a **New node file** template computes its target filename from the note's own title, so each capture can land in its own file.

- **Directory**: vault-relative folder the file is created in; blank means the vault root. An unseen folder is created on the first capture into it — nothing to set up ahead of time.
- **File name pattern**: the filename's stem (`.org` is appended automatically), built from `%<...>` strftime tokens (`%Y` `%m` `%d` `%H` `%M` `%S`) and `%(slug)` — the title, lowercase-preserving, with whitespace collapsed to underscores.
- **New file template**: the org text a brand-new node file starts with, typically a blank `#+title:` line. You don't write the `:ID:` yourself: every node file automatically gets a `:PROPERTIES:` drawer with a fresh `:ID:` at the top. If the template still has its own `:ID:`, the editor warns you and that `:ID:` is ignored; any other properties in its drawer are kept.

The title is never asked for via a prompt dialog. The draft opens with the cursor already on the blank `#+title:` line; type the title directly into the draft, the same way you'd type any other text. The filename is (re-)computed from that line's current value each time the draft saves or autosaves — same as a regular template's heading is only checked when it saves, not prompted for up front. A blank title blocks saving.

What happens on save depends on whether the computed filename already exists:

- **New file**: the whole draft (front matter and body) is written out as the new file's contents, with the `:ID:` drawer added on top. The drawer is never shown in the capture editor.
- **Existing file** (for example a daily-note pattern with no `%(slug)`, so every capture that day resolves to the same filename): like a regular template, the capture editor shows only what you're adding, not the file's existing content, and the target bar marks the file as **existing**. The new body is appended at the bottom, verbatim, with no heading inserted and the file's original title/properties drawer never duplicated. If the file has no `:ID:` yet, one is added.

If you edit the title after the draft has already autosaved once under a slug-based pattern, the newly-resolved filename is what a later autosave targets; the earlier file it first created is left as-is rather than renamed.

Saving (not autosaving) a node closes the capture screen and shows a "Saved" snackbar naming the file, with a **Visit file** action that opens it in read mode.

### Creating a node from a text selection

With [Roam Features](/features/settings-overview#roam-features-experimental)' **Show suggestions while typing** on, selecting a run of text in a roam file's body — the main note editor, the whole-file editor, a daily note, or a Roam-kind capture draft (including one appending to an existing file, like a daily note), with or without the keyboard up — offers a chip per eligible **New node file** template (one whose title line is actually typed, not derived or fixed). Tapping a chip either links the selection to an already-existing node with that exact title, or creates a brand-new node from the template and links to it — no dialog, no extra screen.

## Notification toggle

A separate toggle on this screen turns on an **ongoing capture notification**: a persistent, low-priority notification that opens the Capture picker in one tap, for quick access without unlocking into the app first.

## Shortcut sync

Configured templates automatically stay in sync with Android's long-press launcher shortcuts on the Bloom app icon; add or remove a template and the shortcut list updates to match, no separate configuration needed.
