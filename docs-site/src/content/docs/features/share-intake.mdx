## How it works

Sharing to Bloom opens the [Capture picker](/features/capture) with the shared content already available to templates:

- The first shared **URL** becomes `%shared_url`; Bloom also fetches the page title in the background so a template can reference it (unless [Fetch link titles](#fetch-link-titles) is off)
- Any remaining shared **text** becomes `%shared_text`

Pick a template as normal; whichever placeholders it uses pull in the shared content automatically.

## Shared content target

Settings → Sharing → **Shared content target** sets where shared content lands, so shares end up somewhere predictable even before you've built out a dedicated share-specific template.

Tap the row to open the same file and heading picker as the archive location. Pick a file, or drill into it and pick a heading. The search box at the top finds any file or heading in your vault. **New file…** at the top of the file list creates a notebook and selects it. The row shows the target as a breadcrumb, for example `inbox › Projects › Reading`.

If the file doesn't exist yet, Bloom creates it on the first share. If the heading was renamed or deleted, the share goes to the file itself and the confirmation says so, so nothing you share is lost.

## Add shared items at

Settings → Sharing → **Add shared items at** chooses **Top** or **Bottom** (the default):

- **File target**: the share becomes a new top-level heading at the top of the file (just above its first heading, below any `#+TITLE`-style lines) or at the end of it.
- **Heading target**: the share becomes the first or the last subheading of that heading.

The row's description spells out where the next share will land.

## Fetch link titles

Settings → Sharing → **Fetch link titles** (on by default) controls whether Bloom looks up a shared link's web page to use its title as the note heading. Some sites only reveal their title after running a script, so for those Bloom loads the page in a hidden browser with JavaScript enabled.

Turn it off to keep sharing fully offline: Bloom makes no request. The link is still labeled with any title the sharing app includes (most browsers send one), otherwise with the URL itself.
