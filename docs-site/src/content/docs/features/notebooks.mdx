Notebooks is Bloom's home screen. Every `.org` file in your configured sync folder shows up here as a notebook card; there's no separate "import" step, no database to seed. If a `.org` file exists in the folder, it's a notebook.

## What each card shows

Every notebook card displays:

- **Monogram icon**: a small colored tile showing the first letter of the notebook's name (its `#+TITLE:` when the display name is set to "Title", otherwise the filename). The color is customizable per notebook (long-press → *Change icon color*); hide the tiles list-wide with **Show file icons in notebooks** in Settings → Notebooks.
- **Notebook name**: the filename by default, or the file's `#+TITLE:` if you've set the notebook display name to "Title" in Settings → Notebooks
- **Note count and last-modified time**: e.g. "9 notes · 21 hours ago"
- **Sync status pill**: appears when a notebook is mid-sync, freshly modified, or has a conflict

## Long-press menu

Long-pressing a notebook card opens a context menu with:

- **Pin to top** / **Unpin**: keep frequently used notebooks at the top of the list, independent of alphabetical or recency order. Pinned notebooks and folders share one Pinned strip, listed in the order you pinned them
- **Move up** / **Move down** (pinned notebooks only): reorder the Pinned strip one step at a time, the same way Favorites reorder in the sidebar
- **Rename**: changes the notebook's name within its folder. Names can't contain `/`; use **Move** to put a notebook in another folder
- **Change icon color**: pick the tile color for this notebook's monogram from the theme palette
- **Force reload**: re-parse this file from disk, bypassing the normal change-detection diff (useful if you suspect Bloom's index is stale)
- **Resolve conflict**: jumps straight to the [conflict resolution](/features/conflict-resolution) screen when a Syncthing conflict copy exists for this file
- **Delete**: see below

### Deleting a notebook is permanent

Android's Storage Access Framework has no system trash for files in a folder you granted, so Bloom deletes the file outright after a confirmation prompt. If your vault syncs with Syncthing and you have its file versioning turned on, the previous copy is kept on the peer and you can restore it from there. Otherwise the file is gone.

### Folder rows

Subfolders in your sync directory show up as folder rows in the list. Long-pressing one opens its own menu:

- **Pin to top** / **Unpin**: a pinned folder moves out of the tree and into the Pinned strip at the top of the list, taking everything inside it along. It shares that strip with pinned notebooks, in the order things were pinned. Tap it to expand its contents in place; a folder big enough to open as its own screen drills in instead
- **Move up** / **Move down** (pinned folders only): reorder the folder within the Pinned strip
- **Rename**: renames the folder and moves every `.org` file inside it, keeping each file's icon color and pinned position. The old, now-empty folder is removed
- **Change icon color**: pick the folder tile's color from the theme palette
- **Delete**: after a confirmation prompt, permanently deletes every `.org` file inside the folder (the same permanent delete as a single notebook) and removes the emptied folder

### Flat list

**Settings → Notebooks → Flatten folders** collapses the tree: folder rows disappear and every note shows as its own row, with its folder path (`projects/clients/`) as a small subtitle. Notes at the top level look unchanged. The monogram letter still comes from the filename, not the folder. While flat mode is on, the drill-down view and expand/collapse-all are hidden, and **+** always creates at the vault root, but you can still move a note between folders from its long-press menu. Pinned notes and pinned folders' contents still show in the Pinned strip, as a flat list.

## Creating a notebook

Tap **+** and give the new file a name. Bloom creates an empty `.org` file in your sync folder immediately (the `.org` extension is added for you if you leave it off).

Use a slash to put the notebook inside folders that don't exist yet: `work/ideas.org` creates a `work` folder with `ideas.org` in it, and `work/2026/log.org` nests two levels deep. A name that ends in a slash, or contains `\ : * ? " < > |`, is rejected and the **Create** button stays disabled.

## Settings

**Settings → Notebooks** collects everything that shapes this list. All of it is view-only; nothing here changes anything on disk.

- **Show file icons in notebooks**: whether each row carries its monogram tile. On by default; turn it off for a plainer, text-only list. The per-notebook color you pick is kept either way, it just isn't drawn while this is off.
- **Flatten folders**: hide the folder tree and list every note in one flat list, each note showing its folder path as a subtitle (see [Flat list](#flat-list) above). Off by default.
- **Notebook display name**: whether the list labels each notebook by its **Filename** or by its `#+TITLE:` (**Title**), falling back to the filename when a note has no title. The monogram letter follows the filename either way.
- **Notebooks sort order**: **Alphabetical** or **Last modified**, plus a separate **Ascending / Descending** toggle. The order applies everywhere — top-level notebooks, folders (a folder sorts by its most recently edited note), notes inside folders, the drill-down view, and flat mode. **Pinned notebooks and folders are excluded**; they always keep their pinned order. Default: Alphabetical, ascending.
- **Ignore list**: files, folders, and patterns to exclude from indexing and sync entirely — an excluded folder is never even scanned, not just hidden after the fact. One entry per line: a bare name (`archive`) matches anywhere in the vault at any depth; a path (`projects/archive`) matches only that exact location; `*`/`?` wildcards match within one path segment (`*.bak`) but don't cross folders. Empty by default. If you were using an `.orgzlyignore` file from an older version, its rules were imported into this list automatically the first time you opened the app after updating.

## Deep links

Bloom registers `bloom://` deep links so widgets, notifications, and shortcuts can jump straight into the app:

- `bloom://note/{id}`: opens a specific note
- `bloom://capture`: opens the capture picker
- `bloom://agenda`: opens Agenda
- `bloom://reminder/...`: used internally by reminder notifications

Links and shortcuts made before the app was renamed from Grove keep working: every `grove://` link opens the same place as its `bloom://` version.
